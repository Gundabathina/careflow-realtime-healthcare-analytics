# Project Summary

*A one-page overview for a first-pass skim. For depth, see

## What it is

CareFlow Analytics is an end-to-end healthcare analytics platform built
on 100% synthetic patient data (generated by
[Synthea](https://github.com/synthetichealth/synthea)). It reproduces
the full stack a hospital system's data team would actually build and
operate: a validated ingestion/transformation pipeline, a dimensional
data warehouse, a governed analytics layer, workflow orchestration, and
two independent BI delivery surfaces.

## The problem it solves

Hospital operations, finance, and quality teams need trustworthy,
timely visibility into encounter volume, readmission trends, length of
stay, cost, provider utilization, and patient demographics -- and they
need to trust that the numbers are correct before acting on them. This
project builds the data platform underneath those questions, not a
single dashboard bolted onto raw data.

## How it's built

| Stage | Technology | Result |
|---|---|---|
| Synthetic data generation | Synthea | 58 patients, full clinical history |
| Transformation | Python, pandas, Parquet | Bronze -> Silver -> Gold, checksum-incremental |
| Warehouse | PostgreSQL 16 | 8 dimensions, 8 facts, 6 marts, transactionally loaded |
| Analytics engineering | dbt | 36 models, 133 tests, independent business-logic reconciliation |
| Orchestration | Apache Airflow | 2 DAGs (22-task full run, 11-task daily incremental), idempotent |
| Delivery | Streamlit + Power BI | 7-page live dashboard; fully specified Power BI build (data model, 39 DAX measures) |
| Quality | pytest | 804 automated tests across every layer |

Full architecture: [`architecture/architecture.md`](architecture/architecture.md).

## What makes it more than a tutorial project

- **Two real bugs found and fixed during development**, both
  documented with root cause and fix: a composite-key grain bug in the
  imaging-study fact table, and a foreign-key violation in the
  warehouse loader's force-reload path. See
  [`technical_highlights.md`](technical_highlights.md).
- **Independent reconciliation, not just unit tests** -- patient
  readmissions and financial totals are computed twice (once in Python
  during Gold modeling, once in SQL during dbt) and a dedicated test
  suite asserts they agree within tolerance.
- **PII discipline enforced as if the data were real**, at three
  independent layers (Gold transformation, dbt model tests, dashboard
  query guard), even though the data is entirely synthetic.
- **Honest data quality reporting** -- the dashboard's Data Quality
  page shows a real, currently-failing Silver check rather than
  filtering it out, because the point of the page is pipeline
  observability, not a sanitized front.
