# Data Ethics

## Synthea: what it is and what it produces

Every record in CareFlow Analytics -- patients, encounters, conditions,
medications, procedures, claims, immunizations, imaging studies -- is
generated by [Synthea](https://github.com/synthetichealth/synthea), an
open-source synthetic patient generator built by MITRE. Synthea
simulates realistic-*looking* clinical histories using published
clinical pathways and statistical models -- it does not sample from,
anonymize, or derive from any real patient's actual record. **No real
patient data has been used at any point in this project.**

## No real patient data, anywhere

This is the single most important fact about this project's data:
nothing here came from a real electronic health record, a real
hospital system, or any real individual. Every "patient" is a
statistical construct. This is stated on every page of the Streamlit
dashboard and throughout the project's documentation, deliberately
repeated rather than mentioned once and assumed remembered.

## Limitations of synthetic healthcare data

Synthetic data is genuinely useful for building and testing a data
platform like this one -- but it has real limits that matter for how
results should (and shouldn't) be read:

- **Clinical pathway simplification.** Synthea's disease progression
  models are simplified versions of real clinical guidelines -- they
  capture general patterns, not the full complexity or edge cases of
  real medicine.
- **Population scale and skew.** This project's dataset is small (58
  patients, 3,180 encounters) and was generated with a fixed seed and
  population size for reproducibility -- it is not representative of
  any real population's size, geographic distribution, or health
  burden.
- **No real comorbidity correlation guarantees.** While Synthea models
  are clinically informed, the specific mix of conditions/medications
  per synthetic patient shouldn't be read as a realistic epidemiological
  sample.
- **Financial figures are illustrative, not benchmarked.** Claim costs,
  payer coverage, and patient responsibility are Synthea's own cost
  models, not tied to any real insurer's pricing or a real hospital's
  actual costs -- see the explicit disclaimer on the dashboard's
  Financial Performance page.
- **Temporal range artifact.** Synthea generates each synthetic
  patient's *entire* life history, so this dataset's date range spans
  decades (1943-2026) even though the "current" synthetic population is
  small -- this is a generation characteristic, not a data quality
  defect (documented in `docs/project_metrics.md` and
  `powerbi/data_dictionary.md`).

## No clinical decision-making

**This platform does not make, support, or inform clinical decisions.**
It is an operational and financial analytics platform -- the kind of
tool a hospital's operations, finance, or quality-improvement team
would use, not a diagnostic tool, a clinical decision support system,
or anything that touches individual patient care. Every dashboard and
document in this project is scoped to operational metrics (encounter
volume, cost, readmission *rates*, utilization) rather than
individual-patient clinical judgment.

## Demographic bias caution

Even with synthetic data, it's worth stating the general principle
explicitly: any analytics platform that segments by age, gender, race,
or ethnicity (as the Readmission Analytics and Patient Population pages
do here) carries a responsibility to present those breakdowns as
*descriptive* patterns in the data, not causal or prescriptive
conclusions. A higher readmission rate in one demographic segment in
this dataset reflects Synthea's generation model for that run, not a
real clinical or social finding -- and even with real data, a
segment-level rate difference would need careful, domain-expert
interpretation before informing any decision. This project's dashboards
deliberately use neutral, descriptive language (e.g. "utilization," not
"performance," on the Provider page) for exactly this reason.

## Responsible interpretation

When presenting or discussing this project (in an interview, a demo, or
a portfolio write-up):

- Always lead with "this uses 100% synthetic Synthea-generated data."
- Never describe a specific number from this dataset as representative
  of real-world healthcare patterns.
- Frame the project around the *engineering* it demonstrates (pipeline
  design, data modeling, testing, orchestration) rather than the
  specific clinical or financial findings the sample data happens to show.
- If asked "would this work on real data," the honest answer is: the
  *pipeline* would need no architectural changes, but a real deployment
  would require HIPAA-compliant infrastructure, real access controls,
  audit logging, and a formal data governance review -- none of which
  this portfolio project implements, because it doesn't need to for
  synthetic data. See `docs/interview_guide.md` for how to discuss this
  in an interview.
